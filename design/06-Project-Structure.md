# Git Repository Project Structure

To manage a cross-language framework efficiently, a monorepo setup using **Cargo Workspaces** for Rust and a **Unified Solution (.sln)** for .NET is the cleanest architecture. This keeps everything version-controlled together and prevents your tools from drifting out of sync.

```text
datalium-strata/
├── .github/                     # CI/CD pipelines (GitHub Actions)
│   └── workflows/
│       ├── rust-ci.yml          # Lints, tests, and builds Rust crates & CLI
│       └── dotnet-ci.yml        # Tests, formats, and packs NuGet packages
│
├── cli/                         # --- THE RUST-BASED CLI BINARY ---
│   ├── Cargo.toml
│   └── src/
│       ├── main.rs              # CLI entry point (parsers via clap crate)
│       └── commands/            # graph, thread, checkpoint commands
│
├── rust/                        # --- THE RUST ECOSYSTEM WORKSPACE ---
│   ├── Cargo.toml               # Cargo Workspace root definition
│   ├── strata-core/             # Core execution engine, graph logic, traits
│   ├── strata-memory/           # Storage adapters (SQLite, Postgres, Redis)
│   └── strata-macros/           # Procedural macros for graph definitions
│
├── dotnet/                      # --- THE .NET ECOSYSTEM WORKSPACE ---
│   ├── Datalium.Strata.sln      # Main Visual Studio / .NET Solution
│   ├── src/
│   │   ├── Datalium.Strata/     # Core C# Engine and execution loop (.csproj)
│   │   └── Datalium.Strata.Storage/ # Storage providers (EF Core / Dapper / Redis)
│   └── tests/
│       └── Datalium.Strata.Tests/   # xUnit / NUnit suite for engine verification
│
├── examples/                    # Shared reference examples for developers
│   ├── dotnet-agent/            # Sample enterprise C# worker service agent
│   └── rust-agent/              # Sample hyper-fast async Tokio Rust agent
│
├── LICENSE                      # Open-source license (Apache 2.0 / MIT suggested)
└── README.md                    # Main repository presentation landing page
```

## 🧱 Structural Integrity Rules

- **Shared JSON/Binary Schemas:** The state structures, checkpoint logs, and graph definitions should share a unified JSON or MessagePack schema. This guarantees that the Rust CLI can flawlessly read checkpoints generated by a C# backend server.
- **Independent Releases:** The Rust workspace and .NET solution can be packaged, tagged, and published independently to Crates.io and NuGet respectively, keeping versioning flexible.
