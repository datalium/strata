## Architectural Spec: Token Streaming & Channel Architecture

**Component ID:** STRATA-SPEC-001  
**Status:** PROPOSED

---

### 1. System Overview & The Streaming Challenge

Multi-agent systems suffer from a core communication asymmetry:

- **The Graph Engine** requires atomic, completed states to reliably execute routing decisions and save transactional checkpoints.
- **The Client UI** requires real-time, token-by-token text streaming to maintain a responsive user experience.

In Python frameworks, streaming often forces the entire graph loop to yield execution mid-node, leading to race conditions and complex asynchronous state locks.

Datalium Strata solves this by decoupling the Graph State Pipeline from the Output Delivery Channel. While a node executes on a native thread pool, it writes text chunks to an isolated, thread-safe, lock-free memory ring buffer. The graph engine pumps tokens out to the client instantly, without stalling or interrupting the node's internal state mutations.

### 2. Streaming Data Flow Architecture

```text
┌────────────────────────────────────────────────────────┐
│                   StateGraph Execution Loop            │
└───────────────────────────┬────────────────────────────┘
                            │ Spawns Node Context
                            ▼
┌────────────────────────────────────────────────────────┐
│               Node Context (IExecutionContext)         │
│  Tracks Engine State & exposes lock-free channels     │
└───────────────┬────────────────────────────────┬───────┘
                │                                │
                ▼ (Asynchronous Token Writes)    ▼ (Mutates Engine State)
┌──────────────────────────────┐          ┌──────────────────────────────┐
│  High-Velocity Pipe/Channel  │          │  Atomic Graph State          │
│  (C# System.Threading.Channels)│          │  (Committed post-completion) │
│  (Rust tokio::sync::mpsc)    │          └──────────────────────────────┘
└───────────────┬──────────────┘
                │ Native Thread-Pool Pump
                ▼
┌────────────────────────────────────────────────────────┐
│      Client Output Stream (SSE, gRPC, or WebSockets)   │
└────────────────────────────────────────────────────────┘
```

### 3. C# Streaming Engine Design (Datalium.Strata.Streaming)

In .NET, we leverage `System.Threading.Channels`. This provides a highly optimized, allocation-free, multi-producer single-consumer (MPSC) queue that interfaces seamlessly with `IAsyncEnumerable<T>`.

#### Core Interfaces & Types

```csharp
namespace Datalium.Strata.Streaming;

public enum StreamChunkType { Token, ToolCall, NodeTransition, Error }

public record StreamChunk(
    StreamChunkType Type,
    string NodeName,
    ReadOnlyMemory<char> Payload
);

public interface IStreamContext
{
    ValueTask EmitTokenAsync(string token);
    ValueTask EmitDiagnosticAsync(StreamChunkType type, string message);
}
```

#### Fluent Graph Node Implementation

```csharp
var graph = new StateGraph<MyState>(initialState)
    .AddNode("StreamLLMResponse", async (state, ctx) =>
    {
        // 1. Initiate the model call, passing the streaming context hook
        await foreach (var token in ctx.Models.StreamAsync("gpt-4o", state.Prompt))
        {
            // 2. Push tokens out to the runtime immediately (Lock-free write)
            await ctx.Stream.EmitTokenAsync(token);
        }

        // 3. Complete node state atomically after the stream finishes cleanly
        return state with { IsStreamCompleted = true };
    });

// 4. Executing the graph while consuming the real-time stream
var runner = graph.Compile();
var graphStream = runner.ExecuteWithStreamingAsync(initialState);

await foreach (var chunk in graphStream)
{
    if (chunk.Type == StreamChunkType.Token)
    {
        Console.Write(chunk.Payload.Span); // Instant, zero-allocation terminal render
    }
}
```

### 4. Rust Streaming Engine Design (datalium-strata-streaming)

In Rust, we utilize `tokio::sync::mpsc` paired with memory-efficient `bytes::Bytes` or `Arc<str>` chunks. This guarantees that tokens generated by background tasks do not hit heap-allocation bottlenecks.

#### Core Engine Architecture

```rust
use std::sync::Arc;
use tokio::sync::mpsc;

#[derive(Debug, Clone)]
pub enum StreamChunkType {
    Token,
    NodeStart,
    NodeEnd,
}

#[derive(Debug, Clone)]
pub struct StreamChunk {
    pub chunk_type: StreamChunkType,
    pub node_name: Arc<str>,
    pub content: Arc<str>,
}

pub struct StreamContext {
    sender: mpsc::Sender<StreamChunk>,
    current_node: Arc<str>,
}

impl StreamContext {
    pub async fn emit_token(&self, token: &str) -> Result<(), StrataError> {
        let chunk = StreamChunk {
            chunk_type: StreamChunkType::Token,
            node_name: self.current_node.clone(),
            content: Arc::from(token),
        };
        self.sender.send(chunk).await.map_err(|_| StrataError::ChannelClosed)
    }
}
```

#### Node Execution Integration

```rust
graph.add_node("StreamLLMResponse", |state, ctx| async move {
    let mut model_stream = ctx.model("gpt-4o").stream_prompt(&state.prompt).await?;

    // Asynchronously consume tokens from the LLM provider
    while let Some(token) = model_stream.next().await {
        // Broadcast the token to the graph consumer instantly
        ctx.stream().emit_token(&token).await?;
    }

    // Complete the node execution block cleanly
    Ok(state)
});
```

### 5. Cross-Language Edge Cases & Mitigations

- **Downstream Backpressure:** If a network connection slows down, the UI reader might lag behind the fast-executing LLM.
    - **Mitigation:** Strata implements a bounded channel buffer (defaulting to 1024 chunks). If the buffer fills up, the executing node drops into an asynchronous pause (`await`), matching the speed of the output stream without consuming system memory.
- **Mid-Stream Error States:** If an LLM stream terminates unexpectedly halfway through an operation, the engine must flag the error cleanly without corrupting the historical state graph.
    - **Mitigation:** Strata injects a `StreamChunkType.Error` token into the public channel, halts the graph loop, and executes the designated rollback checkpoint policy designed in our resilience spec.
- **Token Ordering Guarantees:** In multi-threaded environments, ensuring tokens are emitted in the correct sequence is critical.
    - **Mitigation:** The streaming channel is strictly single-producer, single-consumer (MPSC), ensuring that tokens are emitted in the exact order they were generated without

### Implementation Status (2026-10-01)

The spec above is the original proposal; read this before trusting its snippets.

- **Built, in both engines:** the bounded channel (1024 chunks, `StreamContext` / `StreamContext.CreateChannel`), backpressure that pauses the writer, and `StreamChunkType` (`Token`, `NodeStart`, `NodeEnd`, `Error`, `Retry`). `run_streaming` / `RunStreaming` (and `resume_streaming` / `ResumeStreaming`) return the receiver plus a handle / task for the result, instead of the `ExecuteWithStreamingAsync` runner shown above.
- **Node signatures:** the async streaming node of section 3 and 4 exists since `design/17-Async-Execution.md`. C#: `AddStreamingNode(name, async (state, ctx, ct) => { await ctx.Stream!.EmitTokenAsync(token, ct); … })`, with the stream on the `NodeContext` and the token a separate parameter. Rust: `add_async_streaming_node(name, |state, ctx| async move { ctx.stream().unwrap().emit_token(…).await; … })`. A sync streaming node (`AddStreamingNode(name, (state, stream) => …)` / `add_streaming_node`) also exists and uses the blocking emits. There is no `ctx.Models`: model access is the application's.
- **Not as specified:** the channel is multi-producer (a parallel group's branches and a subgraph's child write to it concurrently), so tokens from different branches interleave; one node's own tokens stay in order. A node stopped by cancellation gets no `NodeEnd`, and the stream ends with the run. See `design/14-Parallel-Execution.md`, `design/15-Subgraph-Composition.md` and `design/17-Async-Execution.md`.
