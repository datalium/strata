# Changelog

What changed in each version of Datalium Strata, newest first, written for someone upgrading.

Every NuGet package, every crate and the `strata` CLI share one version and are released together (`design/36-Packaging-And-Versioning.md`). Versions follow semantic versioning. While the version is `0.x`, a minor version may break the API, and this file says what; a patch version doesn't. A preview (`-preview.N`) promises nothing between previews.

Each entry ends with the wire formats that version writes and reads. The rules behind them are in `schema/README.md`, "Compatibility".

## 0.9.0-preview.1 (2026-10-28)

The first version with a number, and the first one published: on nuget.org, on crates.io and as a GitHub release with the `strata` CLI. Before it, applications pinned a commit of this repository.

Why 0.9 and why a preview: the 2026-09-21 evaluation called the state of that day 0.3.0 and set gates for what follows. The gate for 0.5.0 (a real application has run on it and its findings are fixed) has been met. Of the four for 0.9, crash-durable checkpointing, storage hardening and benchmarks are built, and this preview, published on both registries, is the fourth.

Built by the Datalium Strata team, developed privately from June 2026 until this release.

### Changes before this version

For applications that pinned a commit of this repository before there were versions. Newest first. Each entry names the design document with the detail.

- **A tool's own `ArgumentException` is no longer mistaken for bad arguments** (`design/20`, `design/44`). .NET's generated dispatch now throws **`ToolArgumentsException`** (`Datalium.Strata.Tools`, an `ArgumentException`, with `ToolName` and `Problems`) for arguments it can't bind, before the tool runs. `StrataAgent` refuses only that back to the model. Before, it also caught a tool's own `ArgumentException` or `JsonException` (a domain check, say), hiding a real failure; that is now the tool's failure, which fails the node or, under `ToolFailures.ReturnToModel`, goes back as `tool 'x' failed: …`.
    - **The model is told what to fix, in the same words in both engines:** `invalid arguments for tool 'lookup': argument 'orderId' must be a string`, `… argument 'count' is missing`, `… the arguments aren't a JSON object`. Before, .NET passed on the parser's message, which named a generated record and a line number. The rule is `ToolArguments.Problems` / Rust `tools::argument_problems`, pinned by the new shared fixture `schema/fixtures/tools/argument-problems.json`; Rust's `#[strata_tool]` now uses it for `ToolArgumentParseFailure`.
    - **.NET's generated dispatch refuses a missing required argument, and null for a non-nullable parameter**, as the manifest says and as Rust always did. Before, the tool ran with `null` or `0`.
    - The registry's `error.type` `invalid_arguments` now means only this. A tool's own `JsonException` is reported by its type name.
    - **Compatibility:** a tool that relied on getting `null` or `0` for an omitted required parameter is now refused; give the parameter a default, or make it nullable. Code that matched an agent's refusal text on the parser's words sees the new words. A hand-written `IStrataToolProvider` that threw `JsonException` or `ArgumentException` for bad arguments should throw `ToolArgumentsException` to keep the agent's refusal.
- **An agent's options can change by turn** (`design/44`). `StrataAgentOptions.ConfigureTurn` (`Action<AgentTurn, ChatOptions>`) and Rust's `AgentOptions::with_configure_turn` (`Fn(&AgentTurn, &mut ChatRequest)`) change one turn's copy of the options before its model call, after the agent has set the tools and response format. `AgentTurn` gives the turn's number, the tool turns before it, the repairs so far and whether it is a repair. For example, a tool call can be required on the first turn only; with `ChatOptions.ToolMode` / `tool_choice` it applied to every turn, so the model could never answer. New .NET `AgentTurn`; Rust `AgentTurn`, `ConfigureTurn`.
- **A cancelled streaming run no longer hangs on a full channel** (`design/17`). The engine's own `NodeEnd`, `Retry` and `Error` chunks waited for room with no token. A consumer that stopped reading and then cancelled the run (an `await foreach` over `ReadAllAsync(token)` with the run's token, say) could leave the run blocked forever, its completion never finishing. Now those chunks are dropped once the level's token fires, as `NodeStart` already was. Both engines.
- **.NET: a handler cancelled while it waits on a full stream sees `OperationCanceledException`.** `EmitTokenAsync` / `EmitDiagnosticAsync` usually threw `ChannelClosedException` instead, because the run ended and closed the channel before the handler's token reached the write. Code that caught `OperationCanceledException` missed it.
- **.NET's recovery count is public** (`design/33`, SG-39). `RecoveryCount` (`Datalium.Strata.Graph`) with `MetadataKey` (`strata.recoveries`) and `Of(checkpoint)` is now `public`, as Rust's `recovery::RECOVERIES_KEY` and `recoveries_of` already were. It is how many times a thread has been recovered since a node last committed. `RecoverOptions.MaxRecoveries` limits it for the driver only; `RecoverAsync` and `RecoverStreaming` always recover, so an application that recovers threads itself reads `RecoveryCount.Of` on the latest checkpoint and stops at its own limit, instead of reading the key by name. No behaviour or wire format changed.
- **Exported definitions mark interrupt boundaries** (`design/48`, SG-37). `ToDefinition()` / `to_definition()` now writes `"interrupt": { "timeout_ms": … }` on every interrupt boundary that is a node: the timeout in whole milliseconds, or `null` for a boundary without one. A plain node, a parallel group, a subgraph node or a map node can each be a boundary; a wait node can't. A boundary's routes are still its `on_reject` / `on_timeout` edges. A level with a boundary is **definition `schema_version` `1.6.0`**, a superset of `1.5.0`; every other level exports exactly as before. The shared validator gains **`STRATA_ERR_BOUNDARY_IN_MAP`** for a boundary in a map's template, which `.compile()` already refused. `strata graph validate`, `check_shape` and .NET's `ToTopology()` refuse (exit 2) an `interrupt` below `1.6.0` or on a wait node, a negative `timeout_ms` (.NET; Rust's type refuses it), and, at a `1.6.0` level only, an `on_reject` edge from a node that isn't a boundary or an `on_timeout` edge from a node with no timeout. `strata graph view` annotates each boundary (`Approve: interrupt boundary, rejects to Abort, times out after 30m to Escalate`, or `…, then the thread ends` when a timeout has no route). New .NET `GraphNodeDetail.Interrupt` (`GraphInterrupt(TimeoutMs)`), `GraphNodeDefinition.Interrupt` (`GraphInterruptDefinition`), `GraphDefinition.BoundaryVersion`, `ValidationErrorKind.BoundaryInMap`; Rust `GraphNodeDef.interrupt` (`GraphInterruptDef`), `schema::BOUNDARY_GRAPH_SCHEMA_VERSION`, `ValidationErrorKind::BoundaryInMap`. **Compatibility:** an exported graph with a boundary changes bytes and version, so a snapshot of one changes, and an older CLI refuses it (`unsupported schema_version '1.6.0'`): upgrade the CLI that gates definitions first. A Rust `match` on `ValidationErrorKind` naming every variant breaks. Checkpoints are unchanged. **New wire format: graph definition `1.6.0`.**
- **The .NET Redis memory store's search no longer drops records** (`design/45`). On Redis 8, an `FT.SEARCH` that returns the documents' fields can leave documents out of its reply, though the index has them: about one search in twenty-five straight after a write under load missed one record or all of them, which the read-your-writes fix couldn't help. `SearchAsync` now asks the index for keys and distances only and reads each candidate's hash in one pipeline, as the Rust store always has, and checks it against the search again. A search costs one more round trip. No API or wire format changed.
- **A Strata Cloud decision says who decided** (`design/30`, SG-38). `CloudDecision` gains `DecidedBy`, `DecidedByEmail` and `Notes` (Rust `decided_by`, `decided_by_email`, `notes`), read from the decision feed's items (contract §5, since 2026-10-22) and null when an older Cloud doesn't send them. `DecidedBy` is the identity the console verified and `DecidedByEmail` the email the IdP vouched for; check those, not `Signal.ReviewerToken`, which the reviewer may set to anything. The signal and the worker are unchanged. **Compatibility:** Rust's `CloudDecision` gains three public fields, so a struct literal of it breaks; .NET's are init-only properties, so the constructor is unchanged. No wire format changed.
- **The Redis memory store finds what it has just written** (`design/45`). On Redis 8 the Query Engine indexes on worker threads after a write returns, so a search straight after an upsert could miss the record, with a FLAT index as well as HNSW: 2 to 6 searches in 150 in CI. `UpsertAsync` / `upsert` and `UpsertManyAsync` / `upsert_many` now return only once the index returns every record they wrote. Each record costs one more query, plus a wait of a few milliseconds while the workers catch up. A record still not indexed after 5 s fails the call with `memory on Redis didn't index record '<id>' within 5 s of writing it`; the record is written, and a retry is safe. No API or wire format changed.
- **Long-term memory: embeddings, the memory helper and hosting** (`design/45`, SG-32, the last of three parts). SG-32 is complete.
    - **An observed embedding call.**
        - .NET: `StrataEmbeddings.GenerateAsync(generator, texts, options, ctx, …)` over any `IEmbeddingGenerator<string, Embedding<float>>`.
        - Rust: a new `Embedder` trait in `datalium-strata-ai`, with `embed` / `embed_with` and **`OpenAiEmbedder`** (`POST /embeddings`, `encoding_format` `float`, `dimensions` only when asked; OpenAI, Azure, Ollama and vLLM; behind the `openai` feature). There is no Anthropic embedder: Anthropic has no embeddings endpoint.
        - Each call is a model call with operation `embeddings`: a span `embeddings <model>`, the input tokens, and the GenAI metrics. Its faults fail the node as a chat call's do: transient with the provider's hint, or fatal.
        - An answer with fewer vectors than inputs fails it fatally (`invalid_response`). A call with no inputs makes no request and records nothing.
    - **The memory helper.** .NET `StrataMemory` (`RememberAsync`, `RememberManyAsync`, `RecallAsync`), Rust `Memory` (`remember`, `remember_many`, `recall`), with `MemoryEntry` and `RecallOptions`.
        - It embeds the text, records it as the record's `Text`, and stores or searches.
        - Vectors are labelled `<provider>/<model>` (the embedder's default model) unless a `Model` / `with_model` label is given.
        - The tenant is the entry's or the recall's own, else the run's metadata `tenant` (`TenantKey` / `with_tenant_key`), else `""`.
        - `RememberManyAsync` makes one embedding call and one `UpsertManyAsync`.
        - Bad keys, metadata and search options are refused with the store's messages before any embedding call.
        - In Rust a failure is a `MemoryError` (`Embedding` or `Store`), which converts into a `NodeError`.
    - **Hosting (.NET).**
        - Registrations: `AddInMemoryMemory()`, `AddPostgresMemory()`, `AddSqliteMemory()`, `AddRedisMemory()` and `AddMemoryStore<TStore>(factory)`.
        - Each registers one memory store as `IMemoryStore` and `IMemoryRetention`. A second replaces the first.
        - Each reuses the `Strata:Postgres`, `Strata:Sqlite` or `Strata:Redis` connection. The rest comes from `Strata:Memory`: `Dimensions` (required), `Index`, `Table`, `Prefix` and `Extension`.
        - The host's start-up migrates or checks the store, so a database that is behind or has other dimensions stops the host.
        - `AddMemory()` registers a `StrataMemory` over the store and the container's embedding generator, with `Strata:Memory:Model` and `TenantKey`.
        - `AddMemoryRetention()` purges hourly from `Strata:Memory:Retention`. `OlderThan` is required; `Namespace` and `Tenant` are optional.
        - **`Datalium.Strata.Hosting` now depends on `Datalium.Strata.AI`.**
    - **Hosting (Rust).**
        - `StrataSettings.memory` (`MemorySettings`) with `open_memory` on the Postgres, SQLite and Redis settings, and `open_in_memory`.
        - `Host::retain_memory(store, MemoryRetentionDriver)`.
    - **Compatibility:**
        - `ModelCallStarted` / `ModelCallCompleted` gain **`Operation`** (`chat` or `embeddings`). In Rust, a pattern that names every field without `..` breaks.
        - .NET's `MemoryIndex` moved from `Datalium.Strata.Storage.Postgres` to `Datalium.Strata.Storage`.
        - `MemoryRecords.CheckMetadata` is now public, and `MemoryRecords.CheckFilters` is new. Rust's `datalium_strata::memory` gains `MemorySearch::validate_filters`, `validate_scope` and `validate_metadata`.
        - Rust's `StrataSettings` gains a field, so a struct literal of it needs `..Default::default()`.
        - A Rust build of `datalium-strata-ai` without the `anthropic` feature compiles again; it exported the Anthropic client unconditionally.
        - .NET hosting: `AddCheckpointStore`, `AddHistoryStore` and `AddMemoryStore` with the port itself as the type (a factory returning `ICheckpointStore`, say) no longer hang the host's start on a registration that resolved itself.
        - A model or embedding generator whose default model is empty is treated as naming none (`unknown`), rather than failing the call.

    No wire format changed.

- **Long-term memory on SQLite and Redis** (`design/45`, SG-32, the second of three parts). Two more memory stores, in `Datalium.Strata.Storage` / `datalium-strata-memory`. Both pass the same shared cases as the in-memory and Postgres stores.
    - **`SqliteMemoryStore`** (.NET `Datalium.Strata.Storage.Sqlite`; Rust `sqlite_memory`) uses sqlite-vec's `vec_distance_cosine` over an ordinary table, so a search is exact and filtered before ranking. Vectors are stored as little-endian float32 BLOBs. Dimensions are recorded per table in `memory_settings` and checked on open. A file can be shared with the SQLite checkpoint store.
    - **sqlite-vec in Rust** is compiled in: `datalium-strata-memory` gains the dependency `sqlite-vec` 0.1.9, registered on each connection the store opens.
    - **sqlite-vec in .NET is the application's.** `Datalium.Strata.Storage` doesn't reference it, because the only NuGet package (`sqlite-vec` 0.1.7-alpha.2.1) adds a public class to the project that references it and fails an arm64 exe's build. Reference that package yourself with `ExcludeAssets="contentFiles"` (win-x64, linux-x64/arm64, osx-x64/arm64), or give the binary's path in `SqliteMemoryOptions.Extension` (default `vec0`). Without it the store refuses with `memory on SQLite needs the sqlite-vec extension: …`.
    - **`RedisMemoryStore`** (.NET `Datalium.Strata.Storage.Redis`; Rust `redis_memory`) needs a server with the Query Engine: Redis 8, or Redis Stack. On Redis 7 it refuses with `memory on Redis needs the Query Engine (Redis 8 or Redis Stack): FT.CREATE is unknown`.
        - Records are hashes under `{prefix}:memory:records:`, searched by one `FT` index (`{prefix}:memory:idx`, FLAT by default or `MemoryIndex` HNSW) with the filters applied before the KNN. Scores are recomputed exactly, ties go by id, and a tie at the cut is fetched whole.
        - Listing and purging read two sorted sets, so they go by id and by age exactly.
        - `UpsertManyAsync` / `upsert_many` is per record on Redis, not atomic.
        - Retries work as in the Redis checkpoint store.
    - **.NET's `InMemoryMemoryStore` now orders ids by their UTF-8 bytes,** as every other store does (new `MemoryRecords.ByteOrder`). It differed from `StringComparer.Ordinal` only between a character outside the Basic Multilingual Plane and one from U+E000 to U+FFFF.

    **No new wire format.** The `memory` component is version 1 in SQLite's `strata_schema_version` and in Redis's `{prefix}:memory:schema`. The layouts are pinned by `schema/fixtures/memory/sqlite-columns.json`, `sqlite-settings-columns.json` and `redis-record.json`. **CI's Redis image is now `redis:8`**, and the checkpoint stores' Redis tests run on it too.

- **Long-term memory: the store** (`design/45`, SG-32, the first of three parts). A memory store keeps records an application finds again by meaning. **The port is in the engine:** `IMemoryStore` / `IMemoryRetention` in `Datalium.Strata.Memory` (Rust `MemoryStore` / `MemoryRetention` in `datalium_strata::memory`), beside the history store.
    - **A record** is a namespace (`incidents`, `runbooks`, …), a tenant (`""` for none), an id, an embedding (its model and vector), JSON content, the text it was embedded from, and string metadata.
    - **Upserts** replace a record but keep when it was created.
    - **A search** ranks one namespace, one tenant and one embedding model by cosine similarity, most similar first and ties by id, with an optional limit, minimum similarity, excluded ids and metadata equality.
    - **Also on the port:** get, delete, a paged listing by id, and a purge by age (optionally by namespace and tenant), oldest first.
    - **Bad input is refused** before anything is written, with the same message in both engines.
    - **`InMemoryMemoryStore`** (exact cosine) is in the engine.
    - **`PostgresMemoryStore`** is in `Datalium.Strata.Storage` / `datalium-strata-memory`. It needs the `pgvector` extension (`CREATE EXTENSION vector`, which its migration runs): an exact search by default, `MemoryIndex.Hnsw` / `MemoryIndex::Hnsw` as an option, dimensions fixed per store and checked on open, retries as the checkpoint stores have, and metrics `strata.memory.operations`, `strata.memory.operation.duration` and `strata.memory.search.results`.
    - Embeddings, the `Memory` helper, SQLite, Redis and hosting are the next two parts.

    **New wire format: memory record `1.0.0`** (`schema/memory-record.schema.json`). **Database: a `memory` component at schema version 1**, with a `memory_records` table, written only by a memory store: a database without memory is unchanged. CI's Postgres image is now `pgvector/pgvector:pg16`.

- **Model routes: failover and hedging across models** (`design/46`, SG-24). **`ModelRoute`** in `Datalium.Strata.AI` (an `IChatClient`) and `datalium-strata-ai` (a `ChatClient`) is a chat client over ordered candidates, each a client with an optional model of its own. A call tries them in order:
    - **It moves on** after a transient fault, a refusal (finish reason `content_filter`), or an answer the route's `Accept` rejects.
    - **A fatal fault stops it** with that candidate's own error.
    - **`HedgeAfter`** (off by default) starts the next candidate beside a slow one: the first accepted answer, or the first stream to produce an update, wins, and the others are cancelled.
    - **Eligibility:** a candidate's `Eligible` check (the application's rules: tenant, budget, tools, context size) skips it for one request.
    - **Health:** a shared `ModelHealth` skips a candidate's health key (its provider, by default) while a `Retry-After` is in force, and, with a breaker, for a while after that many transient failures in a row.
    - **No retries:** the route never retries a candidate itself. The node's `RecoveryPolicy` retries the whole route.
    - **When nothing answers,** the node fails transiently, with the shortest wait until a candidate is free as its retry hint, or fatally when every candidate was ineligible.
    - **A stream** fails over only until its first update.

    Anything that takes a client takes a route: `StrataChat` / `complete_with`, model nodes and agents.

    **Observation:** through `StrataChat` / `complete_with`, every attempt is its own model call (`ModelCallStarted` / `ModelCallCompleted`, now with `Route`), under a `strata.route` span named `route <name>`. A new run event **`ModelRouted`** says which candidate answered and what happened to every other (`ModelRouteOutcome`). `OnRouted` / `on_routed` reports the same outside a run.

    **New engine and telemetry pieces:** `ModelRouteScope` and `ModelCallInfo.Route` / `.Candidate` (Rust `route` / `route_candidate`). New metrics `strata.route.calls`, `strata.route.failovers`, `strata.route.hedges` and `strata.model.breaker.transitions`.

    **Compatibility:**
    - Rust's `ChatClient` gains a default method `as_route`.
    - Rust's `RunEventKind::ModelCallStarted` / `ModelCallCompleted` gain a `route` field, so a pattern naming every field without `..` breaks.
    - A .NET `switch` over run events sees one new kind.

    No wire format changed.

- **Distributed execution is the application's** (`design/47`, SG-26, closed by decision). Strata doesn't place runs on workers. Partition by thread with your own broker or queue, and leases, durable recovery, the drivers and the per-process scheduler make any placement safe. design/47 writes the pattern down. Nothing changed.
- **Agents: the model ↔ tool loop, with typed answers** (`design/44`, SG-23, the second of its two parts). **`StrataAgent<TOutput>`** in `Datalium.Strata.AI` (Rust **`Agent<O>`** in `datalium-strata-ai`) is a value a node runs: `RunAsync(messages, ctx, ct)` / `run(messages, &ctx)` makes turns of one model call through `StrataChat` / `complete_with` (so each turn streams, is observed and fails like any call, its span tagged `strata.agent`), dispatches the tool calls in the answer through a `ToolRegistry` (a subset, its middleware included) with the node's context, the agent's id as caller id and the model's call id, sends the results back in one tool message in the model's order, and stops at an answer without tool calls, which it returns as an `AgentResult` (output, the whole conversation, usage summed over the turns, turns, every tool call and how it went). A typed agent asks for its output type's JSON schema as the response format (.NET from `AIJsonUtilities`, every property required and no others allowed; Rust from `#[derive(StrataSchema)]`, made strict-compatible), parses the answer (a Markdown fence removed), runs `Validate`, and sends a bad answer back to be repaired up to `MaxRepairs` (1) times; `StrataAgent<string>` / `Agent<String>` returns the text. **Tool names are made provider-safe** (`ToolDeclarations.For(registry)` / `ToolDeclarations::for_registry`: `[a-zA-Z0-9_-]`, at most 64 characters, `_2`, `_3` for a collision, in registration order) and mapped back before dispatch, so events, spans and middleware see the Strata name. **Refusals go back to the model** as `{"error": "…"}` (not found, not permitted, denied by middleware, arguments that don't parse); **any other tool failure fails the node** (in .NET a tool's own `NodeException` as it is, anything else through the fault classifier; in Rust fatal unless `AgentOptions::with_fault_classifier` says otherwise), or goes back to the model too with `ToolFailures.ReturnToModel`. More than `MaxTurns` (8) tool turns, or an answer still bad after its repairs, fails the node transiently, so a retry starts the conversation over. A turn's tool calls run one at a time unless `ToolConcurrency` says more. `AddAgentNode` / `add_agent_node` runs an agent as a fallible node. **Two behaviour changes in Rust:** `#[derive(StrataSchema)]` now describes nested derived types, `Vec`s, slices, arrays and sets (`array` with `items`), maps with string keys (`object` with `additionalProperties`) and fieldless enums (a `string` `enum`), honours `#[serde(rename)]`, `#[serde(rename_all)]`, `#[serde(skip)]` and `#[serde(default)]`, and bounds a generic type's parameters by `StrataSchema`, so **a tool's manifest changes**: a `Vec<String>` parameter is an `array` (it said `object`), and a field of a type that implements nothing is still `object`; `StrataSchema` is implemented for strings, booleans, numbers and the standard containers. And **a model's tool call whose arguments aren't a JSON object no longer fails the call** (`invalid_response`): `Content::ToolCall.arguments` keeps the model's text as a `Value::String`, which an agent refuses back to the model, as `Microsoft.Extensions.AI` does in .NET. No wire format changed.
- **Model calls from a node** (`design/44`, SG-23, the first of its two parts). Two new packages: **`Datalium.Strata.AI`** (on `Microsoft.Extensions.AI.Abstractions` and `System.ClientModel`) and the crate **`datalium-strata-ai`** (on `reqwest` with `rustls`). `StrataChat.GetResponseAsync(client, messages, options, ctx, …)` (Rust `complete(&client, request, &ctx)` / `complete_with`) asks a model for an answer from inside a node: it streams when the run streams, each piece of text reaching the run's stream as a `Token` chunk, and is one request otherwise; either way the whole answer comes back. A provider's fault fails the node the way design/25's retries read it: 408, 409, 429 and every 5xx are transient and carry the provider's `retry-after-ms` / `Retry-After` as the retry hint, every other 4xx is fatal, and a stream that breaks after it started is transient. `AddModelNode` / `add_model_node` (on the new `StateGraphAiExt`) adds one call as a fallible node. In .NET any `IChatClient` works; `ModelFaults` reads `HttpRequestException` and `ClientResultException` (the OpenAI and Azure SDKs'), an `IModelFaultClassifier` reads anything else, and `RetryAfterHandler` keeps the hint for an `HttpClient`-based provider (turn the SDK's own retries off). In Rust, Strata's own `ChatClient` trait, with `OpenAiChatClient` (Chat Completions: OpenAI and any compatible server, Ollama and vLLM included) and `AnthropicChatClient` (Messages), both streaming over server-sent events, neither retrying, behind the default features `openai` and `anthropic`. **The engine gains `ModelCallScope`** (.NET `Datalium.Strata.Observability`, Rust `observability`), through which any client puts a call in its run: new run events `ModelCallStarted` and `ModelCallCompleted` (model, call id, result, the provider's usage, finish reason, duration), a `strata.model` span named `chat <model>` with the OpenTelemetry GenAI attributes, and the metrics `gen_ai.client.token.usage`, `gen_ai.client.operation.duration` and `strata.model.time_to_first_chunk`, all from the engine's existing source. Prompts and answers are never recorded. A .NET `switch` over run events, and a Rust `match` on `RunEventKind` (non-exhaustive already), sees two new kinds. The agent is the entry above. No wire format changed.
- **Leases and thread listing on the Strata Cloud store** (`design/43`, SG-36). `StrataCloudCheckpointStore` now has the five lease members and the query port (.NET `ICheckpointQuery`, Rust `CheckpointQuery`), over Strata Cloud's lease routes and `GET /v1/sdk/threads` / `GET /v1/sdk/checkpoints` (its SDK contract §11, §12). So against Cloud **a run with a lease is no longer refused**: it acquires, renews, saves every checkpoint under the lease's token and releases, and a save after another owner took the thread ends the run `Cancelled(LeaseLost)` with nothing written; and **`WakeDueAsync`, `RecoverStaleAsync`, a `LevelSignals.Due` resume of a listed thread, and the hosted wake and recovery drivers run on Cloud**. In .NET, `AddCloudCheckpoints()` now registers the store as `ICheckpointQuery` too; the retention driver still refuses it (Cloud keeps its own retention). An acquisition carries an `Idempotency-Key`, so retrying it after a lost answer is safe. A listing page may be short while more follow, with Cloud's own cursor: follow `NextCursor` until it is null, as the engine's drivers do. Cloud's lease limits apply (a ttl of 1 s to 1 h, an owner of at most 256 bytes); outside them the call fails with Cloud's `422`. New `StrataCloudWire.LeaseTokenHeader`, `IdempotencyKeyHeader`, `LeaseLostCode` (Rust `wire::LEASE_TOKEN_HEADER`, `IDEMPOTENCY_KEY_HEADER`, `LEASE_LOST_CODE`), and in `datalium-strata` `ThreadSummary::new`. `datalium-strata-cloud` gains the dependency `uuid` (already in its tree, through `datalium-strata`). Needs a Strata Cloud at Phase 10b or later. No wire format changed.
- **Waking a due thread through your own resume** (`design/42`, SG-35). `LevelSignals.Due` (Rust `LevelSignals::due()`, and `due_at(now)`) makes `ResumeAsync` and `ResumeStreaming` (Rust `resume_with`, `resume_streaming_with`) do for one thread what `WakeDueAsync` does: decided at the resume's own load, on the run's `TimeProvider` (Rust `Utc::now()` or `now`), a due timer continues, a due timeout takes its route, and a due timeout with no route ends the thread `timed_out` and returns `Cancelled(Ended)`. A thread that isn't due, waits with no time, or isn't this graph's is refused with nothing written, and the stamp and the end stay conditional, so a `Due` resume and a wake driver can't both wake one thread. So an application that lists due threads itself (`ThreadQuery.DueBy`) can wake each with its own run options, observer, priority and lease, concurrently, and **a woken run can stream**. `LevelSignals.Event(EventSignal)` (Rust `LevelSignals::event`) answers an event wait through the same resumes, so a signalled run can stream too. A wake or event signal refuses signals for outer levels. A `Due` resume that ends a thread reports itself as the resume it was called as (`RunStarted(Resume)`, then `CheckpointSaved(Ended)` and `RunCompleted(Cancelled, Ended)`). `WakeDueAsync`, `SignalAsync` and every existing resume behave as before. No wire format changed.
- **Value offload** (`design/41`, SG-15, the last of its three parts). A Postgres, SQLite or Redis checkpoint store given `Offload` (`OffloadOptions` on `PostgresStoreOptions`, `SqliteStoreOptions` and `RedisStoreOptions`; Rust `with_offload(Offload::new())`) stores each top-level value of a level's state whose JSON is at least 64 KiB (`Threshold`) once, in a blob store, and refers to it from the row; a value that doesn't change isn't written again. The blobs go to the store's own database (a `checkpoint_blobs` table, a Redis hash per thread, written with their row), or to an `ICheckpointBlobStore` / `BlobStore` the options name: `InMemoryCheckpointBlobStore` and `FileSystemCheckpointBlobStore` are built in (Rust `InMemoryBlobStore`, `FileSystemBlobStore`), and S3 and the like go through the port. A load checks each blob against its hash and fails, naming it, when one is missing or doesn't match. A purge deletes a thread's blobs, and the Redis finished-thread ttl expires them with the list. With a 64 KiB payload that never changes, a twenty-node run stores about 3.4 KB a save, against 65.6 KB whole and 6.6 KB as deltas. Off by default; a store reads such rows whatever its own options, from the blob store they name. Hosting: `Strata:Postgres:Offload`, `Strata:Redis:Offload`, `Strata:Sqlite:Offload` with `Enabled`, `Threshold` and `Path` (a filesystem blob store), or a registered `ICheckpointBlobStore` (Rust `offload.enabled`, `threshold`, `path`); Rust's settings structs gain a field. The CLI reads offloaded rows from the database, and from a filesystem blob store with `--blobs <dir>`. New metrics `strata.store.blobs` and `strata.store.blob.size`; `strata.store.checkpoint.size` gains the encodings `offloaded` and `delta_offloaded`. `datalium-strata-memory` gains the direct dependency `sha1_smol` (already in its tree, through `redis`). **A delta now also checks its base row's content**, not only its sequence: a thread id purged and run again by another process up to the sequence a store remembered could take a wrong delta before; in SQL the base row's `created_at` must match, in Redis the SHA-1 of its element. The Redis save scripts and `PURGE_SCRIPT` take the blob hash as a key, and the save scripts the base's SHA-1 and the blobs as arguments. **New wire format: checkpoint `1.9.0`**, written only by a store with offload on, for a row that refers to a blob; **database: the `checkpoints` component's schema version 2** (`checkpoint_blobs`), which a current store applies when it opens a database, offload or not, so an older runtime then refuses the database: upgrade every reader of a store, the CLI included, before a current writer opens it.
- **Delta checkpoints** (`design/41`, SG-15, the second of its three parts). A Postgres, SQLite or Redis checkpoint store given `Deltas` (`PostgresStoreOptions.Deltas`, `SqliteStoreOptions.Deltas`, `RedisStoreOptions.Deltas`; Rust `with_deltas(Deltas::new())`) stores a `running` checkpoint as the top-level keys of each level's state that changed since the thread's previous row, when it knows that row, with a whole row every 16 (`FullEvery`) and every other checkpoint whole. A delta is appended only if the row it is a delta of is still the thread's latest, in the same atomic step; otherwise the checkpoint is stored whole. With a 64 KiB payload that never changes, a delta row stores about 100 bytes and a twenty-node run a tenth of what it did. **Every store reads such rows whatever its own options**, and so does the CLI: the engine never sees them. Off by default. Hosting: `Strata:Postgres:Deltas`, `Strata:Redis:Deltas`, `Strata:Sqlite:Deltas` with `Enabled` (Rust `deltas.enabled`); Rust's `RedisSettings` gains a field, so a struct literal of it needs `..Default::default()`. `strata.store.checkpoint.size` gains the encoding `delta`, and the Redis store now records it. `datalium-strata-memory` gains the dependency `sha2`. The Redis save scripts take one more argument, and the fenced one returns the list's length when it saves. **New wire format: checkpoint `1.8.0`**, written only by a store with deltas on, for a row stored as a delta: upgrade every reader of a store, the CLI included, before turning deltas on, since an older one refuses such a row. No database change.
- **Group commit, and a connection pool for Rust's Postgres stores** (`design/41`, SG-15, the first of its three parts). A Postgres or SQLite checkpoint store given `GroupCommit` (`PostgresStoreOptions.GroupCommit`, the new `SqliteStoreOptions`; Rust `with_group_commit(GroupCommit::new())`) flushes saves that arrive while others are being written together, in one transaction: each save keeps its own answer (saved, lost its race, lease lost), one thread's saves keep their order, a save is answered only once its flush has committed, and a save alone is flushed at once. Up to 4 flushes run at once in Postgres (`MaxConcurrentFlushes`), one in SQLite. Measured with 64 writers: Postgres about 2.3 to 3 times the saves a second, SQLite 13 to 15 times. Off by default; Redis has none (its connection already pipelines concurrent saves, and a batch measured no faster). Hosting: `Strata:Postgres:GroupCommit` and `Strata:Sqlite:GroupCommit` with `Enabled` (Rust `group_commit.enabled`). **Rust's Postgres stores now keep a pool** of connections (`deadpool-postgres`, a new dependency of `datalium-strata-memory`; 16 by default, `with_pool_size`, Rust `postgres.pool_size`) and prepare each statement once per connection: sixteen writers save about eleven times as fast as before, and one writer about 1.8 times. A store built with `from_client` keeps its one client. `EfCoreCheckpointStore`'s constructor gains an optional fourth argument. New metrics `strata.store.flush.size`, `strata.store.flush.wait` and `strata.store.checkpoint.size`. No wire format changed.
- **A run scheduler** (`design/40`, SG-25). `RunScheduler` (.NET `Datalium.Strata.Scheduling`, Rust `datalium_strata::scheduler`) admits runs to a fixed number of slots: higher priority first, slots reserved for high priorities, a concurrency limit per tenant (a metadata key, `tenant` by default; 0 pauses one), and a bounded queue that sheds its lowest-ranked run for one that outranks it. Give it to a run with `RunOptions.Scheduler` and `Priority` (Rust `RunConfig::with_scheduler` / `with_priority`): every run mode and both drivers then wait for a slot before they load or write anything. A run it doesn't admit returns the new `NotAdmitted` result (it refines `Failed`; Rust `StrataError::NotAdmitted`) with nothing written. Ending a thread takes no slot. Hosting: `AddScheduler()` from `Strata:Scheduler` (Rust `StrataSettings.scheduler`, `Host::close_on_shutdown`), and the wake and recovery drivers take a priority. New run event field `RunStarted.QueuedFor` (Rust `queued_for`, which breaks a pattern naming every field of `RunStarted` without `..`), span tags `strata.run.priority` and `strata.scheduler.wait_ms`, and four metrics (`strata.scheduler.admissions`, `.wait`, `.queued`, `.active`). A run with no scheduler behaves as before. No wire format changed.
- **Inline sync nodes in Rust** (`design/39`). `add_inline_node` and `add_inline_fallible_node` take the same handlers as `add_node` and `add_fallible_node` and run them on the executor instead of tokio's blocking pool: a node costs about 0.4 µs instead of 4 to 5 µs, and no longer varies from run to run. For handlers that compute and return; one must not block, can't be abandoned, and `.compile()` refuses a timeout on it. Nothing else changes, and the .NET engine has no counterpart. No wire format changed.
- **The Rust engine costs a node 0.4 µs, not 1.8** (`design/38`). The first benchmark run found the Rust engine 2.6 to 7.5 times slower than the .NET one. It was making 28 heap allocations for every node; it makes one. A hundred async nodes now traverse in 41 µs (185 before; .NET 50). No API, wire format, event, span or metric changed. One corner did: a handler that cancels the token it was given (`ctx.cancellation()`) and goes on waiting is no longer stopped and reported as timed out. `datalium-strata` gains the dependency `pin-project-lite`. Sync handlers, parallel groups, maps and streaming are still slower in Rust than in .NET, for reasons the document gives.
- **Benchmarks** (`design/37`). A benchmark suite in both engines, with the first results in `benchmarks/RESULTS.md`. Nothing in any package changes: the benchmark crate and project are not published. With it, three of the evaluation's four gates for 0.9 are met; a pre-release published on both registries remains.
- **Graph identity** (`design/31`). A graph compiled with an id and a version writes them on every checkpoint, and refuses a thread another graph or version wrote. Nothing changes for a graph without one.
- **Thread leases** (`design/32`). A run given a lease holds its thread in the store, and a save from an owner that was replaced is refused. New `CancelReason.LeaseLost`. A store decorator must forward the five lease members.
- **A checkpoint per node, and crash recovery** (`design/33`). `CheckpointPolicy.EveryNode`, `RecoverAsync`, `RecoverStaleAsync`, `NodeContext.IdempotencyKey`. **Breaking for a graph that opts in:** a resume no longer writes `resumed_at`, the thread state `Resumed` is never seen, and a `running` thread refuses a resume, a signal and a wake.
- **Storage hardening** (`design/34`). The Postgres and Redis stores retry transient failures, and look before repeating a save that may have happened. `PurgeAsync` deletes finished threads. **Breaking in .NET:** the Postgres stores no longer create their tables in the constructor (call `MigrateAsync` or use `OpenAsync` if your own SQL reads the tables first), and `ownsDataSource` now follows a new options argument.
- **Hosting** (`design/35`). New packages. The engine's wake and recovery drivers take a stop token.
- **Packaging** (`design/36`). This version, the generator inside the `Datalium.Strata` package, XML docs and symbols.

### Wire formats

|                                   | Writes up to                                                                                                                                     | Reads                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Checkpoint `schema_version`       | `1.7.0`; `1.8.0` from a store with deltas on, for a row stored as a delta; `1.9.0` from a store with offload on, for a row that refers to a blob | `1.0.0` to `1.9.0` (a store decodes `1.8.0` and `1.9.0` rows; the engine never sees one) |
| Graph definition `schema_version` | `1.6.0`                                                                                                                                          | `1.0.0` to `1.6.0`                                                                       |
| History record `schema_version`   | `1.0.0`                                                                                                                                          | `1.0.0`                                                                                  |
| Database, `checkpoints` component | 2                                                                                                                                                | 0 and 1 (migrated on open) and 2                                                         |
| Database, `history` component     | 1                                                                                                                                                | 0 (migrated on open) and 1                                                               |
| Memory record `schema_version`    | `1.0.0`                                                                                                                                          | `1.0.0`                                                                                  |
| Database, `memory` component      | 1 (a memory store only; in Redis, `{prefix}:memory:schema`)                                                                                      | 1                                                                                        |

A graph that uses nothing new still writes `1.0.0` checkpoints, byte for byte. Strata Cloud must accept checkpoint versions `1.6.0` and `1.7.0` before a graph with an identity, or one that checkpoints every node, can save there.
